매장 POS 판매 기록 + 외부 신호 → 다음 날 메뉴별 판매량 범위(p10·p50·p90)와 준비량. LLM은 숫자를 만들지 않고 경고 문장만 쓴다. · 저장소 naeil-myeotgae 브랜치 ml-engine · 2026-11-16 기준

2. 깨지면 안 되는 규칙

  • 시점 규칙: D일 예측은 D−1일 영업 종료(issue_time)에 낸다. 판매 이력은 shift(1) 뒤 계산, 신호는 published_at ≤ issue_time 중 가장 늦은 값. 누수 테스트 2개가 지킨다.
  • 비율 목표: y = qty / base_level (mean_28→mean_7→lag_1, 최소 1). 예측 = 비율 × base. 이력 변수도 같은 단위(r_*).
  • 학습 제외: 품절일(정답이 수요의 하한), 메뉴 첫날(base 없음).
  • 신호 채택: 자료 있는 묶음의 모든 조합 중 M1보다 전체 WAPE↓ 그리고 검증 구간 과반 개선 → 그중 WAPE 최저 (pick_combo).
  • 최종 테스트: 모든 결정 후 딱 한 번. 결과를 보고 고치지 않는다.
  • 짧은 데이터(120일 미만): 검증 2×7일 + 테스트 7일, 작은 모델. data_note에 자동으로 밝힌다.
  • LLM: 판매량 숫자 생성·수정 금지. 인용은 코드가 원문 대조.

5. 모델과 신호 묶음

모델쓰는 정보
M07일 전 같은 요일 판매량 그대로 (기준선)
M1판매 이력 + 비율 이력 + 매장 흐름 + 요일·공휴일 + 메뉴·온도 표기
M2M1 + 날씨 temp_diff(기온−최근 28일 평균), rain_mm
M3+ 학사일정·행사(exam_period·vacation·festival·nearby_event·*_diff), 유행, 기념일
이름 규칙: 채택 없음=M1, 날씨만=M2, 그 외 하나라도=M3. 실제 쓴 신호는 signals_used·decisions.
