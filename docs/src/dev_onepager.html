2. 깨지면 안 되는 규칙

  • 시점 규칙: D일 예측은 D−1일 영업 종료(issue_time)에 낸다. 판매 이력은 shift(1) 뒤 계산, 신호는 published_at ≤ issue_time 중 가장 늦은 값. 검색량 유행은 D−2일까지만 쓴다.
  • 비율 목표: y = qty / base_level (mean_28→mean_7→lag_1, 최소 1). 예측 = 비율 × base. 이력 변수도 같은 단위(r_*).
  • 학습 제외: 품절일(정답이 수요의 하한), 메뉴 첫날(base 없음).
  • 신호 채택: 자료 있는 묶음의 모든 조합 중 M1보다 전체 WAPE 3% 이상↓ 그리고 검증 구간 과반 개선 → 그중 WAPE 최저 → 빼도 나빠지지 않는 묶음은 뺌 (pick_combo).
  • 최종 테스트: 모든 결정 후 딱 한 번. 결과를 보고 고치지 않는다.
  • 짧은 데이터(120일 미만): 검증 2×7일 + 테스트 7일, 작은 모델. data_note에 자동으로 밝힌다.
  • LLM: 판매량 숫자 생성·수정 금지. 근거·인용은 코드가 원문과 대조. 같은 입력은 저장된 응답 사용.
  • 커밋 금지: .env, data/raw/(실제 POS), data/artifacts/(매장별 결과).

python run.py --store sinchon-a --demo        # 가상 1년, 약 40초
python run.py --store s --pos pos.xlsx --address "주소"
python run.py --store s --from-step predict   # 예측만 다시
uvicorn backend.app.main:app --port 8000      # 웹 API
cd frontend && npm run dev                   # 화면

5. 모델과 신호 묶음

모델쓰는 정보
M07일 전 같은 요일 판매량 그대로 (기준선)
M1판매 이력 + 비율 이력 + 매장 흐름 + 요일·공휴일 + 메뉴·온도 표기
M2M1 + 날씨 temp_diff(기온−최근 28일 평균), rain_mm
M3+ 학사일정·행사(exam_period·vacation·festival·nearby_event·*_diff), 유행(trend_level = 메뉴 검색량 최근 7일 ÷ 그 전 28일), 기념일(special_day)
이름 규칙: 채택 없음=M1, 날씨만=M2, 그 외 하나라도=M3. 실제 쓴 신호는 signals_used·decisions.

한계 · 범위 적중 목표는 80%. · 가상 매장은 우리가 만든 효과라 실제보다 쉽다. · 빵집 테스트 구간은 한 번 본 뒤 고침 → 독립 확인 아님. · 가장 강한 단순 규칙(같은 요일 4주 평균×최근 흐름) 대비로는 가상 −20%, 빵집 −10%. · 과거 날씨는 그때의 예보가 아니라 관측값을 대신 씀. · 유행(검색량)과 팝업·뉴스 신호의 효과는 실매장 데이터로 아직 검증하지 못함. · 한 달치 데이터에서는 신호 채택이 어렵고 흔들린다.
